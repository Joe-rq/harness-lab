## 沉淀要点（人工确认）

### 可复用模式

1. **守卫会把错误承诺写成"必须存在"**。`tests/governance.test.mjs` 的短语表要求 README / command / skill 里必须有 `npx --yes --package=harness-lab ...`——测试是对的（它保证三处一致），但它锁定的是一个**已知为假**的承诺。可复用做法：改任何对外命令前，先 `grep -rn` 全仓找"谁在强制它"；如果守卫在强制旧形式，**换形式不降强度**（必需短语换成有证据的形式，旧形式移入禁用表防回流）。
2. **一个承诺通常印在多处**。本次三处：README + `.claude/commands/harness-setup.md` + `.agents/skills/source-command-harness-setup/SKILL.md`，后两者随包发布、是用户安装时 agent 直接读的资产。只改 README 等于半个修复。可复用做法：把"发布资产"也纳入 grep 范围（`.agents/`、`.claude/commands/`、`context/`），不只 README。
3. **文档里的命令必须有运行证据**。不要发明命令形式；去测试里找已被执行的等价物（本次取自 packed-install fixture：`npm exec --offline --yes --package=<tarball> -- harness-install`，registry 指向不可达端口）。文档命令 = 测试命令，才不会漂移。
4. **撤承诺 ≠ 静默删除**。撤 Windows 支持时保留了"未验证 + 4 项失败 + run ID"——删掉承诺却不留警示，等于把风险从文档转移给用户。
5. **`blocked` 与 `suspended` 是两个语义**：blocked = 待补的欠账；suspended = 已决定不做/暂不做。用错会让下个会话白干（把暂停项当欠账去补）。

### 踩坑

1. **scope-guard 会把 CANNOT 段里的反引号路径变成 deny**。为说明"只允许改这一处测试"而在 CANNOT 里写了 `tests/governance.test.mjs`，结果它成为 deny 模式，把该文件的写入也拦掉。可复用做法：**CANNOT 段不要出现任何你想要允许的路径**，用描述性表述代替。
2. **文件层状态改了，事件层不会变**。事件 schema 没有 `req_suspended`，投影的搁置列表由 `req_blocked` 事件硬编码 `status: 'blocked'` 生成，因此 REQ 文件转 suspended 后 `session-start` 仍显示 blocked。可复用做法：改任何"状态字段"前，先列出所有消费方（文件解析 vs 事件投影 vs 缓存），逐个确认。
3. **门禁的 allow 提取器认相对路径**：`cd /tmp && mkdir pkg` 里的相对路径会被当作仓内目标拦截；仓外写入在有活跃 REQ 时一律拒绝。要在仓外做验证，先想清楚是否需要豁免，或换个不需要写的验证方式（本次改用"引用测试里已执行的命令"）。
