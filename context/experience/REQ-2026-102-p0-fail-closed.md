# 2026-09-23 P0 必需章节 fail-closed（缺章节/空章节一律拒绝启动）

## 场景（来自 REQ 背景）

产品承诺（README「生命周期」段与 `AGENTS.md`）："空模板 REQ 既不能通过 PreToolUse，也不能执行 `req:start`"、"只有补齐真实背景、目标、验收标准后，REQ 才能通过 hook 与 `req:start`"。**当前实现做不到**——这是 2026-07-16 路线报告的 D2，两条路线都标记为必修。

根因（实测）：`scripts/req-validation.mjs:28-32` 的 `getSection()` 在标题不存在时返回**空字符串**，而占位符检查是"空串里是否包含占位词"——恒为 false，于是**缺章节的 REQ 一路绿灯**：

```
findReqTemplateIssues('# REQ: x\n\n## 目标\n- 真目标\n')   // 缺 背景 / 验收标准
→ []                                                        // 期望：两个 missing-section
```

另一处根因（本次实测撞到）：占位符检查是**子串匹配**，因此"正文里引用了占位符字面量"也会被判为"占位符未替换"——本 REQ 起草时在背景里引用模板占位句，`req:start` 直接拒绝（起草者不得不先把那行字面量改写成省略式才能启动）。这是同一天第四个"把文本当数据"的同族缺陷：占位符只在**行首**（去掉列表标记后）出现时才算未填，句中被引用不算。

同一漏检还有**第二份实现**：`scripts/req-check.js:119-136` 自己维护一套占位符正则，只查占位符、同样不查缺失；两份实现各自 fail-open，修一处不影响另一处。

路线报告的原始记录见 `docs/plans/2026-07-harness-lab-product-route-decision.md` D2："章节不存在时返回空字符串，但只检查空字符串是否包含已知占位词……与'背景、目标、验收标准未写实不能启动'的核心承诺相冲突。"

课程判据（L5）："放一个故意违规的样本，命令必须抓出来退非零"——本 REQ 的验收方式照此设计。

## 沉淀要点（人工确认）

### 可复用模式

1. **fail-open 的典型形状：在空值上做检查**。`getSection()` 找不到标题时返回空串，占位符检查于是变成 `''.includes(x)`——恒 false。可复用检查法：任何"检查某段文本是否违规"的校验器，先问"这段文本取不到时返回什么"，把"取不到"单独当成一类问题，而不是让它自然流过检查。
2. **判定要区分"内容"与"提及"**。同一天四个缺陷（豁免自举、CANNOT 路径、heredoc 正文、占位符引用）都是同一个根因：把**提及**当成了**内容**。写校验器时用"行首锚定 + 归一化"而不是子串匹配，能同时避免这类假阳性。
3. **同一判定只能有一份实现**。本次发现三份占位符实现（`req-validation`、`req-check` 的检查、`req-check` 的阻断消息），且三份都是子串匹配。修一处不生效；门禁类逻辑必须单点，消费者只负责渲染。
4. **两个方向都要有证据**：该拒的拒（故意缺章节的样本被真实 `req:start` 拒绝）+ 该放的放（正文引用占位符的 REQ 通过校验）。只有拒绝方向的证据，很容易在"修掉假阳性"时把真拦截一起修没。
5. **用自己当活体样本**：把一个"修复前会被拦"的输入留在交付物正文里（本次是 REQ 正文中的占位符引用），修复后它的存在本身就是通过的证明。

### 踩坑

1. **正则 `\n+` 是隐蔽的越界来源**：标题后的 `\n+` 贪婪吃掉空行，使"空章节"把下一个标题吞进正文，空章节因此漏判。凡是"标题 + 内容 + 下一个标题"的结构，宁可只吃一个换行。
2. **改共享模块时先确认没人删过东西**：本次一次大段替换误删了同文件里的 `parseReqStatus`，导致生命周期/worktree/tarball/block 五个流程用例全红——错误信息（`ReferenceError`）出现在 hook 子进程里，先在测试里看到的是"流程失败"而非"函数缺失"。大段 Edit 后应立刻跑一次全量测试。
3. **门禁的假阳性会挡住修它的 REQ**：起草 REQ-102 时，正文引用占位符 → PreToolUse 阻断写入 → 只能改写措辞。这类"修 bug 的工单本身被 bug 挡住"的自举问题值得在门禁类 REQ 里优先识别（与 REQ-2026-100 的豁免死锁同族）。
