## Release Conditions

- 发布说明需注明行为变化：**heredoc 正文不再参与写目标解析**。此前 `git commit -F - <<'MSG' … MSG`、`bash <<EOF` 等命令的正文若含 `>` / `<`，会被误判为写操作（无活跃 REQ 时直接阻断）。
- 发布说明需注明取舍：`bash <<EOF` 这类"正文喂解释器"的写法与"`perl -e` / `python -c` 解释器写"同属已声明的不可封边界（README「已知限制」与 `AGENTS.md` 已写明）。
- 头部与同行的真实重定向识别不变；`tee` / `cp` / `sed -i` / 复合重定向等既有模式不受影响，24+ 条断言保持通过。
- 已安装的消费方若自定义了写目标模式：本改动只影响"命令字符串里 heredoc 正文"的解析，不改变其他输入的处理。

## Rollback

- `git revert` 本 REQ 提交即可：改动集中在 `write-target-policy.mjs` 的入口预处理（新增两个内部函数 + 一行调用）、1 条测试与两处文档；无数据迁移。
- 回滚后 heredoc 正文重新被扫描，含 `<`/`>` 的正常提交会再次被误拦。

## Conclusion

- Ready for handoff。同族第三个门禁缺陷关闭（前两个：豁免文件写不进去、CANNOT 段路径变 deny，均由 REQ-2026-100 修复）；三个缺陷的共同根因是"把非命令文本当命令解析"，本 REQ 之后该类假阳性在 heredoc 形态上清零。
